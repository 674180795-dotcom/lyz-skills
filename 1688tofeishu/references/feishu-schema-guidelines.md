# 飞书多维表格与云文档交付规约 (Feishu Sourcing Data Standards)

> 📌 本文档规范 1688 供应商询盘结果向飞书多维表格（Bitable）与飞书云文档（Docx）交付时的数据结构、排版审美与合规边界。

---

## 🚫 1. 严格禁止技术噪音 (No Technical Noise)

面向真实商业决策与手机端消费，严禁向多维表格或云文档透传以下技术字段：
- ❌ **内部哈希/规范ID**（如 `prd_tok_...`、MD5）；
- ❌ **口令与短链代码**（口令易失效且排版凌乱）；
- ❌ **Agent 防御性推理说明**（如“检测到展示销量...”占用空间无意义）；
- ❌ **置信度英文代码**（如 `L2_SALES_SIGNAL_OBSERVED`）。

---

## 📊 2. 多维表格标准字段架构 (Bitable Schema)

在 Base 中统一创建以下业务字段：

1. `工厂全称`（文本，Primary 主字段，例：`杭州卡浓服饰辅料有限公司`）
2. `对接状态`（单选：`已出详细报价` / `仅报部分单价` / `确认工艺但未报价` / `仅回打招呼/确认中` / `超时未回复`）
3. `工艺方案建议`（文本，例：`斜纹布数码印+绣边+魔术贴背胶`）
4. `打样/版费`（文本，例：`¥150元 (3-4天)` / `¥180元 (大货做货全退)`）
5. `大货单价(1000套)`（文本，例：`¥1.20/个`）
6. `背卡与包装费`（文本，例：`包装¥0.20/个(含OPP) + 背卡¥190/千张`）
7. `普票税点`（文本，例：`3个点 (+3%)` / `1个点 (+1%)`）
8. `11.15能否发货`（单选：`可以满足` / `交期紧张需尽快定样` / `无法满足/直接拒绝` / `待确认`）
9. `综合推荐评级`（单选：`⭐⭐⭐⭐⭐ 首选推荐` / `⭐⭐⭐⭐ 备选跟进` / `⭐⭐⭐ 报价偏高/能力受限` / `❌ 暂不考虑/无实质回复`）
10. `核心沟通记录与商务建议`（文本，包含优劣势分析与落地建议）

## 📱 3. 移动端优先云文档排版 (Mobile-First Docx)

1. **绝对禁止宽表格**：
   - 严禁输出 3 列以上的横向 Markdown 表格，彻底杜绝手机端横向拉动与行高塌陷；
2. **全面采用“垂直卡片流”**：
   - 使用 `> ` 引用块封装各工厂属性，形成天然移动端卡片；
   - 配合胶囊标签（`` `标签` ``）与加粗键值对；
   - 使用 A/B 纵向对比列表（`❌ 传统痛点` 与 `✅ 优化方案`）；
   - 使用 `Step 01` -> `Step 02` 步进序列呈现落地排期；
3. **视觉美感原则**：
   - 节点前置具象 Emoji（🎯、💡、⚠️、📌、🛠️、📦）；
   - 严格遵循“单段 3 行原则”，段落间使用 `---` 留白透气；
4. **统一自动归档**：
