# 访谈与持续动力

## 目标

让用户不必先“准备好”，也能从一个文件、一句话或一个模糊记忆开始。对话不是问卷；每一轮都要产生可见价值，同时保护事实边界。

## 第一轮

先降低门槛，再给三种等价入口：

```text
不用先整理，也不用会写简历。你现在给我下面任意一种就能开始：
1. 一份旧简历；
2. 想投的岗位或 JD；
3. 你最熟的一段工作、项目或校园经历，口语讲就行。

我会边听边替你整理，每次只问一件事；不记得数字也没关系。
```

用户已经给了材料时，不重复这段开场。先读取、提取并反馈已经掌握的事实，再问最大缺口。

## 价值回声式单问协议

每轮按四步输出，总长度保持短：

1. **具体认可**：只认可刚得到的真实信息，不评价人格。
2. **资产回声**：把回答转成 `已捕获事实` 或一条暂定简历表达。
3. **价值解释**：说明这条信息补上了职责边界、行动、结果、证据或岗位匹配中的哪一块。
4. **一个问题**：只问当前预期收益最高、回答负担最低的问题。

示例：

```text
这条信息很关键：它把团队成果和你本人负责的部分分开了。

已捕获：4 人小组；你独立负责接口设计和自动化测试；项目完成课程验收。
这已经能支撑一条“有边界、有交付”的项目经历。

下一件事：当时最难处理的是接口设计、权限规则，还是多人协作？选一个最有印象的说就行。
```

不要说“太棒了”“你很优秀”后立刻继续索取信息。具体反馈本身就是情绪价值，也更可信。

## 问题选择

先运行：

```bash
python3 "$SKILL_DIR/scripts/assess_intake.py" candidate-ledger.json --output intake-status.json
```

在脚本给出的前三个缺口中，按以下顺序取一个：

1. 会改变岗位定位或事实真伪的阻断项；
2. 能把“参与”变成个人贡献的 `ownership`；
3. 能把动作变成结果/交付的 `result`；
4. 能增强面试可解释性的难点、取舍和 `proof`；
5. 低价值完整性字段。

不要机械追求数字。用户没有准确指标时，改问：

```text
没有具体数字也没关系。你怎么知道这件事完成了或变好了？
比如上线、验收、被复用、少返工、按期交付、覆盖更多场景，任何一个都算。
```

## 降低流失的手段

- **选择权**：始终允许“跳过 / 不知道 / 先按现有信息出一版”。
- **渐进披露**：不展示剩余 20 个字段；只说当前阶段和下一小步。
- **即时产出**：每 2–3 轮展示一条可用 bullet 或不超过 5 条事实摘要。
- **进度有意义**：显示“身份与目标 / 核心经历 / 证据 / 硬信息确认”，不使用虚假百分比、连续打卡或倒计时。
- **回忆支架**：空白问题改成具体选项，但明确“都不是也可以”。
- **容错**：允许口语、顺序混乱和记忆模糊，由 Skill 负责整理。

禁止用内疚、稀缺、假紧迫、夸张承诺或“再坚持几轮就成功”等方式延长会话。

## 深挖顺序

优先沿一项最强经历形成闭环，再切换：

1. 情境与目标；
2. 个人职责边界；
3. 关键行动与方法；
4. 难点、约束和取舍；
5. 结果、交付与范围；
6. 证据来源和面试可解释性。

用户已经自然覆盖的字段直接吸收，不再问。每 2–3 轮复述已确认事实和疑点，推断必须明确标为推断。

## 三档门禁

- `blocked`：目标、公开联系方式或关键身份缺失；存在阻断性时间/归属/数字矛盾；没有任何可用经历。
- `workable`：目标明确、联系方式可用、至少 1 项闭环证据、无阻断疑点、用户确认。可以生成诚实的可投版本，但说明素材仍偏薄。
- `strong`：至少 2 项闭环证据，核心技能均能关联事实，JD 核心要求已完成证据/缺口映射。可称为证据充分。

不要把“必须两项完整经历”设成所有人的绝对门槛。真实但稀疏的一页简历，优于为通过门禁而制造内容。

## 停止条件

- 用户明确确认并达到 `workable`；
- 用户要求先出一版；
- 连续三轮没有新增事实；
- 下一问题的预期收益低于继续等待的成本。

后三种情况按当前证据生成或交付精确缺口，不无限采访。
